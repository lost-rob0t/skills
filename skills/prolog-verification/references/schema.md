# Workspace verification schema

`facts.kb` is a ground-term projection of observed workspace state. The helper owns these predicates:

```prolog
task(TaskId).
repo_state(Head, WorktreeDigest).
research_required(Boolean).
observation(Id, command(Argv), exit(Status), OutputDigest, Head, WorktreeDigest).
brave_search(QueryDigest, ResultDigest, RetrievedAt, Head, WorktreeDigest).
```

Agents may add task-specific predicates such as `requirement/2`, `supports/2`, or domain facts. Keep observations generated by `prolog-verify`; do not hand-write successful command or Brave evidence.

`knowledge.kb` is generated from the durable Prolog knowledge DB and contains active applicable records:

```prolog
long_term_knowledge(Id, Scope, Owner, Kind, Key, Value, Source, Status, CreatedAt, UpdatedAt).
```

It also defines convenience views:

```prolog
remembered(Key, Value).
known_bug(Key, Value).
known_failure_path(Key, Value).
known_invariant(Key, Value).
known_decision(Key, Value).
known_workaround(Key, Value).
known_warning(Key, Value).
```

These predicates are historical/contextual knowledge. They may guide or constrain a proof, but they are not substitutes for `observation/6` or other current-state evidence.

`verify.pl` must load both `facts.kb` and `knowledge.kb`, define a semideterministic `complete/0`, and run focused PlUnit tests. A useful extension pattern is:

```prolog
requirement_satisfied(Requirement) :-
    requirement(Requirement, _),
    supports(Observation, Requirement),
    observation(Observation, _, exit(0), _, Head, Digest),
    repo_state(Head, Digest).

complete :-
    base_complete,
    forall(requirement(Requirement, _),
           once(requirement_satisfied(Requirement))).
```

A durable invariant can be referenced explicitly without treating it as proof of current behavior:

```prolog
forbidden_regression(Name) :-
    known_failure_path(Name, _).
```

Do not infer that an unobserved condition is false. Represent an unresolved condition explicitly or make `complete/0` fail until evidence exists.

The worktree digest excludes `.git/` and `.prolog/`, so recording, recalling, or checking evidence does not invalidate itself. In Git repositories it covers the binary diff from `HEAD` plus untracked, non-ignored files.
